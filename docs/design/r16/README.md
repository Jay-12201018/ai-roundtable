## 核心思路

1. **讨论是唯一的主角。**像 Claude 一样：左侧是房间和讨论记录，中间是居中的阅读栏，底部是圆角输入框。成员发言不加气泡、像正文一样阅读；主持人的话放在右侧气泡里，一眼分得清“谁在说话”。
2. **主持人的手不离开输入框。**运行中，输入框就是插话框：直接打字是插话，输入 `@` 点名下一位，点「设为持续指令」把这段话变成长期规则；「开始讨论」的位置原地变成「暂停 / 继续」（保留 D098）。原来很长的右侧「主持人控制」面板因此只剩查看用的「本场信息」，分成 进度 / 成员 / 指令 / 产物 四个标签。
3. **附加信息分层，不堆在正文下面。**身份一行（头像、名字、模型）；正文；只有需要处理时才出现一条提示（受影响、写到上限、预算停下），提示里带着唯一的下一步按钮和费用；版本、花费、复制、修改、重新生成收在一行浅色的页脚里。
4. **默认就能用，配置只做一次。**首次使用有“连接模型 / 先试玩”两条路；连接模型是三步向导（选服务 → 粘贴 Key → 检查）；新房间默认三位成员（起草 · 审查 · 综合）；讨论方式按房间记住，不用每次“验证并应用”。
5. **诚实地说钱和风险。**每个会花钱的按钮旁边写最高花费；“已预留”“未知（按上限计）”“已核销”分开写；危险操作（停止、删除）用红色描边，与普通按钮在视觉和位置上分开。

## 十个已知体验问题的解决方式

**1. 设置页文案太技术化、页面太长、每次启动都要确认会话目标**
- 用三步向导代替长表单：选服务（DeepSeek / OpenAI / Claude / Gemini / 其他兼容服务 / 演示）→ 粘贴 Key → 检查连接。服务预设带好官方地址和模型，用户一般只需要粘贴 Key。
- 文案改写示例：
  - 「模型 ID 属于当前实例；允许手动输入，不以模型列表作为白名单」→「名字照服务商文档填写；列表里没有的也可以手动加。」
  - 「仅允许 HTTPS 或明确的 localhost、127.0.0.1、[::1] HTTP；不得含凭据、查询参数或片段……」→「一般不用改。地址必须以 https:// 开头（本机服务可以用 http://localhost）。」（细则在输入不合格时再就地说明。）
  - 「配置检查仅校验本地设置。获取模型列表、鉴权与真实生成相互独立……」→ 两个按钮：「检查连接 · 免费，不生成内容」「试发一条 · 约 ¥0.0001」。
- 会话目标确认：把“确认这把 Key 发往哪里”放在**保存 Key 的同一步**（地址写在输入框正上方，按钮叫「保存并连接」），之后不在每次启动重复问。这改变了安全行为，见 **决定 D1**。

**2. 每跑完一次工作流都要回去“验证并应用”**
讨论方式成为房间的一项设置：选一次，房间记住；每次开始讨论时由 Main 按当时的成员自动预览校验（等价于今天的 previewWorkflow），通过就直接开始，不通过就在输入框上方说明哪里不对。输入框上的「审查修订链 ▾」胶囊随时可以改。见 **决定 D2**。

**3. 右侧主持人面板太长、预算停下后仍显示灰色的重试/续写、有“事件序列”开发信息**
- 插话、点名、新增持续指令都回到输入框；面板只剩“查看”，分四个标签，每个标签一屏放得下。
- 重试 / 续写只出现在出问题的那条发言上，并且只有 Main 允许时才显示（`canCommand` 为真），预算停下时完全不出现，只出现“追加并继续”。
- 事件序列、运行 ID、同步状态折叠进「运行详情（排查问题时用）」。

**4. 消息身份行太重，附加信息堆在正文下**
身份一行只放名字和模型显示名（「起草者 · DeepSeek Flash」），Provider 名、模型 ID 进“请求详情”。附加信息分三层：头部标签（修订、主持人点名、已由摘要代替）→ 需要处理的提示条（受影响、截断，带唯一的动作和价格）→ 浅色页脚（版本、来源、金额、操作）。

**5. 窄窗口横向滚动（`body min-width:1080px`）**
去掉固定最小宽度，按 800 / 1024 / 1280 / 1600 四档折叠（见[响应式规则](#响应式折叠规则)）。窗口最小尺寸建议改为 800×600（`createMainWindow.ts`，总控文件）。

**6. 成员名与角色关系不清（用户把成员叫 A/B/C，角色写“起草者”）**
- 添加成员先选**角色模板**：起草、审查、综合、反方、事实核查、自定义。选了就自动填好名字、角色和设定，都能改。
- 表单里写清两者的区别：“名字：显示在讨论里，随你取，比如‘老周’或‘B’”；“角色：决定 TA 做什么。起草、审查、综合会自动带上内置的发言要求”（对应 D095 按角色名匹配的内置指引）。
- 讨论中身份行显示名字；房间页和本场信息的成员行写“角色：审查”。名字已经包含角色词时（如“审查者”）不重复显示角色标签。
- 新房间默认带三位成员（起草者 / 审查者 / 综合者，模型用默认服务的默认模型）。见 **决定 D5**。

**7. 首次使用不知道从哪开始**
没有任何服务时，主区域是欢迎页：两张卡片「连接模型服务」（主推）和「先试玩演示」（Mock，写明“回复是预先写好的示例，不代表真实模型的水平”），下方三步说明和一句数据/Key 安全说明。连接完成后自动建好第一个房间。见 **决定 D6**。

**8. 本机代理只能用环境变量开启**
设置 › 网络与代理：开关、地址（只能选 127.0.0.1 或 [::1]）+ 端口、“由代理解析域名”勾选（对应 `ROUNDTABLE_TRUST_PROXY_DNS`，并说明代理能看到访问了哪个服务、看不到 Key 和内容）、「检测代理」、改动重启生效。安全语义不变：仍只用于 DeepSeek / Claude / Gemini 的固定官方地址与固定路径（D093）。见 **决定 D3**。

**9. 保留已有的好设计**
- 开始按钮原地变「暂停」，暂停后同一位置变「继续」（D098）；在原型里三者同宽、同位置（`.controls .slot`）。
- 输入区固定在窗口底部，控制条是它的最后一行；停止确认、预算提示都出现在控制条上方，不挤动「暂停」。
- 停止要确认：有请求在途时写清“已发出、可能已计费、拿不到用量时按上限 ¥0.0386 计入”；默认焦点“不停止”，Esc 取消。
- 「每回合后暂停」默认不勾选，本机记住（D099）。
- 单次输出上限在「⋯」里，默认 4096，写清“约 3,000 汉字”与续写。

**10. 为 R14、R15 预留位置**
本场信息 › 产物：方案文档、对比表、行动清单、代码候选四类入口，写法区分“可以生成 / 草稿待确认 / 已校验 / 已导出”。产物查看时临时占用主区域（顶部有“返回讨论”，保留阅读位置和草稿）；代码候选打开后是“文件列表 + diff + 目标路径校验 + 逐个文件确认写入”，按钮不叫含糊的“应用”。原型里这一栏标注了“预留位置”。

| 范围 | 设计要求 |
| --- | --- |

| 双主题 | 跟随系统 / 浅色 / 深色，切换即生效并记住；所有组件只用 token，不写死颜色。 |
| 可访问性 | 见下方“可访问性要点”。 |

### 间距、圆角、阴影、图标

- 间距刻度 `4 / 8 / 12 / 16 / 24 / 32 / 48`。阅读栏最大 760px（正文 720px 左右），发言之间 30px，区块之间 32px。
- 圆角：标签 6、按钮/输入 8、卡片/弹层 12、对话框 16、输入框 20、胶囊全圆。
- 阴影只有三种：`--shadow-1`（分段控件选中）、`--shadow-composer`（输入框浮在内容上）、`--shadow-pop`（弹层、抽屉、对话框）。不用渐变装饰（输入框上方的淡出只为遮住滚动内容）。
- 图标：线性 1.6px、圆角端点、16/20px，与已在依赖里的 `lucide-react` 一致；图标按钮点击区至少 30–32px，并有文字名称（`aria-label` + `title`）。
- 应用标志：一个圆环 + 六个小圆点（“围坐一桌”），墨绿单色，不借用任何既有品牌图形。

## 关键交互说明

- **开始 → 运行 → 暂停 → 继续/下一步 → 停止**：控制条在输入框右下角，顺序为「停止」｜间隔｜「下一步」「暂停/继续」。主按钮槽位固定宽度，开始、暂停、继续轮流占用。状态以 Main 快照为准：点暂停后显示“正在暂停 · 等起草者说完”，Main 确认后才变「继续」。
- **插话与点名**：运行中（含暂停）输入框占位符写“插话，所有成员从下一回合起可见；输入 @ 点名下一位”。`@` 菜单列出成员与是否可点（例如“不在当前阶段（复审）”“不在本次讨论方式里”），底部写清“排在下一回合，不打断正在进行的发言”。一条带 `@` 的插话 = 先点名再插话（见决定 D4）。
- **持续指令**：输入框写好后点「设为持续指令」，发送后进入本场信息 › 指令，可修改、清除，写明“从下一次发言起生效”。
- **停止确认**：弹层出现在停止按钮正上方，焦点在「不停止」；确认按钮是红底红框，和普通按钮区分。
- **预算停下**：时间线末尾一张卡片：原因（下一次最多花多少、只剩多少）、金额输入（默认至少补足差额、不低于 ¥1）、「追加并继续」；控制条的「继续」变灰并在下方写“先在上方追加预算”。
- **受影响 / 截断 / 摘要**：提示条里的按钮就是唯一的下一步，旁边写最高花费；摘要待确认时，卡片里「确认使用」是主按钮。
- **金额**：页脚金额可点击（不是只靠悬停），弹出 tokens、缓存命中、计价时段、是否已核销；未知费用在此核销。
- **抽屉与对话框**：有标题和关闭按钮，Esc 关闭，焦点限制在内部，关闭后回到触发按钮；遮罩下的内容不可交互。
- **新讨论**：标题“这场讨论要解决什么？”，写明成员会按哪种讨论方式发言；可选的建议目标来自最近的讨论标题（只填进输入框，不自动开始）。

### 可访问性要点

- 所有操作可用键盘完成；焦点轮廓 2px `--focus`，不裁切。
- 状态都有文字，颜色只做辅助（运行中、已暂停、已因预算停止、可以使用、还没填写 Key…）。
- 流式输出不逐字播报：发言开始、结束、暂停、停止、错误各播报一次（`role=status` / `alert`）。
- `prefers-reduced-motion` 时去掉运行中圆点闪烁、光标闪烁、平滑滚动和抽屉动画。
- 200% 缩放时按可用宽度进入窄档布局，输入框、状态、停止始终可见。

## 响应式折叠规则

断点按应用窗口的**可用宽度**（缩放后），原型用容器查询实现，实现时用 `ResizeObserver` 或容器查询都可以。

| 可用宽度 | 左侧导航 | 讨论 | 本场信息 | 其他 |
| --- | --- | --- | --- | --- |
| ≥ 1280 | 常驻 256px，可收起 | 阅读栏居中，最大 760px | 常驻 320px，可关；关后讨论区变宽但阅读栏不超过 760px | — |
| 1024–1279 | 常驻 | 同上 | 右侧抽屉（遮罩），默认关闭；点预算胶囊或面板按钮打开 | — |
| 800–1023 | 左侧抽屉，标题栏出现菜单按钮 | 占满宽度，左右 20px 边距；标题栏只留标题、状态、预算胶囊和面板按钮 | 右侧抽屉 | 统计卡片两列；选择卡片两列；设置子导航变成顶部横向标签 |
| < 800 | 不支持（窗口最小 800×600） | | | |

窄窗口下输入框控制条可能换行：先换“胶囊”一行，控制按钮始终整组留在右下。长标题单行省略，完整标题在悬停提示和本场信息里。

## 需要你确认的决定

### D1 · 请求地址怎么确认（取代“每次启动确认会话目标”）

| 选项 | 做法 | 好处 | 代价 / 风险 |
| --- | --- | --- | --- |
| A 维持现状 | 每次启动后，每个真实服务都要在设置页确认一次 | 最保守；改了地址或 Key 一定会被看到 | 每次启动都要做一遍，用户已明确觉得烦；容易养成“看都不看就点确认”的习惯，安全价值递减 |
| **B 保存 Key 时确认，之后记住（推荐）** | 「保存并连接」按钮上方写明地址，点击即确认；Main 持久记住“这把 Key（修订号）+ 这个地址 + 服务类型”的绑定；Key、地址或类型任何一项变了，绑定立即失效，需要重新确认 | 确认发生在用户真正关注地址的那一刻；之后启动不再打扰；仍然防住“Key 被发到别的地址” | 需要 Main 持久化确认记录（KeyService/ProviderRegistry + 可能一个 migration，总控处理）；有本机数据库写权限的人可以伪造确认——但这样的人本来就能读到更多东西，威胁模型不变 |
| C 开始讨论时统一确认 | 每次启动后第一次开始讨论，在开始按钮处弹一次“本次将向以下地址发送：…” | 一次确认多个服务；仍是会话级 | 每次启动仍要确认一次；打断开始讨论的动线 |

建议：**内置官方地址的服务用 B；用户自己填写地址的兼容服务用 B 加一层——在讨论开始前显示一次“将发往 xxx”提示（C 的轻量版）**。

### D2 · 讨论方式按房间记住

| 选项 | 做法 | 好处 | 代价 |
| --- | --- | --- | --- |
| A 维持现状 | 每次运行后都要回工作流页“验证并应用” | 无改动 | 用户实测中反复踩到 |
| **B 先在本机记住（推荐先做）** | Renderer 按房间把所选配置存进 localStorage；每次开始时调用现有 `previewWorkflow` 校验，通过就带上 previewId 开始 | 不改 Schema、不加 migration，第二步就能做 | 只在这台电脑、这个 profile 有效；清浏览器存储会丢（会退回默认“自由讨论”并提示） |
| C 存进数据库 | rooms 表增加 workflowConfig（或新表），由 Main 保存 | 跨重装、与导出一致 | 需要总控分配 migration、改 Shared/IPC |

建议先 B，C 留给后续总控排期。

### D3 · 代理设置入口

| 选项 | 做法 | 好处 | 代价 |
| --- | --- | --- | --- |
| A 维持现状 | 只能在启动前设置 `ROUNDTABLE_CONNECT_PROXY` 和 `ROUNDTABLE_TRUST_PROXY_DNS=1` | 不改代码 | 国内用户要会改环境变量，门槛高 |
| **B 设置页入口，重启生效（推荐）** | 设置写进 Main 的本地配置（仍只接受 127.0.0.1 / [::1] + 端口，必须显式勾选“由代理解析域名”）；启动时读取；环境变量优先并在页面上说明来源；提供「检测代理」「立即重启」 | 语义与现在完全一致（启动时决定、固定官方目标）；改动面小 | 需要新的 Main 配置读写 IPC 和重启 IPC（总控）；检测代理要发一次不带 Key 的 CONNECT 握手 |
| C 设置页入口，立即生效 | 运行时替换网络层 | 不用重启 | 要处理进行中的请求和已建立的连接，风险和测试量都大 |

### D4 · 运行中输入框兼作插话，`@` 同时点名

| 选项 | 做法 | 好处 | 代价 |
| --- | --- | --- | --- |
| **A 输入框即插话；`@成员` = 点名 + 插话（推荐）** | Renderer 先发 `setOverride` 再发 `interject`；任一步失败都在原地说明，已成功的那步不会被悄悄撤回 | 与 Claude 输入习惯一致；面板大幅缩短 | 两个命令不是原子的（点名成功、插话失败时要清楚提示）；插话正文里会保留 `@审查者` 字样（对模型无害，模型文本本来就没有调度权限） |
| B 点名和插话分开 | `@` 菜单只点名，不发送文字 | 实现最简单、语义最清楚 | 想“让 B 下一个说并且告诉他重点”要两步 |
| C 新增合并命令 | Main 提供一个原子的“点名 + 插话” | 原子 | 改 Shared 契约和 IPC（总控），收益有限 |

### D5 · 角色模板与默认成员

| 选项 | 做法 | 好处 | 代价 |
| --- | --- | --- | --- |
| **A 只在界面预填（推荐）** | 模板只填写名字、角色、设定文本；“反方”“事实核查”的要求写在设定里 | 不改 Main 的上下文构建（D095） | 反方/事实核查没有 Main 内置指引，效果完全取决于设定文本 |
| B 同时扩充 Main 内置指引 | 在 D095 的角色匹配里增加反方、事实核查 | 质量更稳 | 改动上下文格式，需要真实模型复测（第三层验收） |

新房间默认三位成员（起草者、审查者、综合者）：没有可用模型时成员状态写“还没选模型”，不会自动改用 Mock。

### D6 · 首次使用时自动建房间

| 选项 | 做法 | 好处 | 代价 |
| --- | --- | --- | --- |
| **A 自动建（推荐）** | 「开始试玩」自动建“演示房间”（三位 Mock 成员）；连接第一个服务后自动建“我的第一场讨论” | 新用户两次点击就能看到讨论 | 会写入数据；用户不需要时要能删除（房间页底部可以删，未讨论过的房间允许删除） |
| B 只预填 | 打开“新建房间”对话框并预填，用户点确认才创建 | 不替用户做决定 | 多一步 |

### 其他会变动行为、但影响较小的点

- 窗口最小尺寸由 1080 宽改为 800×600（`src/main/windows/createMainWindow.ts`，总控）。
- “检查连接”合并今天的“检查配置 + 测试鉴权”（都不产生生成费用）；“获取模型列表”移到“添加模型”菜单。
- 用量页加时间范围选择（本月 / 上月 / 全部）：需要 `usage.getReport` 支持时间范围，或先在 Renderer 过滤日期汇总（按讨论汇总不能简单过滤，需总控评估）。

| 主持人面板 | `HostPanel` + App 里的重试/恢复按钮 + 事件序列 | 拆入输入框、消息、提示卡片和「本场信息」四个标签 |
| 设置 | `SettingsFeature` 一个 380 行的长表单 | 服务列表 + 详情 + 三步向导 + 网络 + 外观 |
| 房间 | `RoomsFeature` 自带左侧列表、标签页（成员/历史） | 房间列表并入全局侧栏；房间页单页 |
| 工作流 | 独立页面，验证 + 应用两步，应用状态存在 App 内存里 | 对话框 + 按房间记住 + 开始时自动校验 |
| 窗口 | `minWidth: 1080` | `minWidth: 800, minHeight: 600` |

## 第二步实现拆分建议

按文件归属切成可以并行的批次。**A 必须先合入**，其余在 A 之后可以并行（各自文件集合不重叠）；B 涉及 App 组装，按规范由总控做或由总控指定唯一负责人。

| 批次 | 内容 | 主要文件 | 依赖 / 归属 |
| --- | --- | --- | --- |
| A 基础 | token、全局样式、基础组件（按钮、胶囊、对话框、抽屉、弹层、标签页、开关、表单字段、提示条） | 新增 `src/renderer/theme/**`、`src/renderer/components/ui/**`；改 `styles.css` | R16。先合入，供其他批次使用 |
| B 外壳 | 侧栏（房间 + 讨论记录，复用 `listRooms`/`listRoomRuns`）、标题栏、本场信息容器、响应式抽屉、窗口最小尺寸 | `App.tsx`（拆出 `AppShell`）、`createMainWindow.ts` | 总控（App 组装、Main 窗口） |
| C 时间线 | 消息、主持人气泡、摘要卡片、提示条、页脚、金额弹层、Markdown 与代码块、虚拟列表与“回到最新” | 新增 `features/timeline/**`；`HostTimeline`、`SummaryViews` 的展示部分迁入；`UsageViews` 的 `MessageUsage` | R16；`features/host` 原 owner 配合迁移 |
| D 输入区与本场信息 | 统一输入框（目标/插话、@ 菜单、持续指令、胶囊、控制条、停止确认）、本场信息四个标签、预算卡片、运行详情 | 新增 `features/composer/**`、`features/runPanel/**`；`HostPanel` 退役 | R16；依赖 D4 决定 |
| E 设置 | 设置外壳、服务列表与详情、三步连接向导（服务预设先内置 DeepSeek/OpenAI/Anthropic/Gemini/兼容/Mock，衔接 [Provider Catalog 规划](../../PROVIDER_CATALOG_PLAN.md)）、外观 | `features/settings/**` | R16。D1、D3 需要的 Main/IPC 改动由总控另做 |
| F 房间、成员、讨论方式 | 房间页、成员对话框与角色模板、拖动排序（含键盘替代）、讨论方式对话框与按房间记住 | `features/rooms/**`、`features/workflows/**` | R16；依赖 D2、D5 |
| G 首次使用与用量 | 欢迎页、演示/首个房间自动创建、用量页换装 | 新增 `features/onboarding/**`；`features/usage/UsagePage.tsx`、`usage.css` | R16；依赖 D6 |
| H 验收 | 四档窗口 × 双主题截图、200% 缩放、键盘与焦点、IME、1000+ 条消息流式性能、实测对比度 | `tests/unit/chatUI/**`、`tests/integration/chatUI/**`、实操探针与截图 | 每批交付时做各自部分，最后汇总 |

建议节奏：A → (B 与 C 并行) → D → (E、F、G 并行) → H。B+C+D 合起来就能替换讨论主界面，是最值得先给用户试用的一刀。

需要总控处理的公共改动（变更申请）：D1 的确认持久化（Main + 可能的 migration）、D2-C（如选）、D3 的代理配置与重启 IPC、窗口最小尺寸、可能新增的虚拟列表依赖（优先自己实现窗口化，不够再申请依赖）。
