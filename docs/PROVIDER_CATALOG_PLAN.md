2026-10-20 用户追加产品需求；**需求已记录，目录实现未启动**。不新增 R 编号，不更改 R00–R18（含 R10A/R10B）的依赖表，不扩充当前 R10A、R10B、R11 的任务书、代码或测试归属。本文件是未来实施和验收依据，不是已实现的 Shared DTO、可用服务商清单或付费测试授权。

## 产品目标与身份

在保留 OpenAI、Anthropic、Gemini 原生适配的基础上，允许使用官方 API、已核实的兼容 API 以及用户自定义 OpenAI-compatible 接入。Kimi、豆包、通义千问、智谱 GLM、MiniMax、OpenRouter、硅基流动、DeepSeek 等是拟核验的服务商/渠道目标，**不是本次已验证的预设**；未来逐项依据官方 API 文档录入。不得把 Coding 套餐、网页订阅账号或未经核实的第三方渠道当作可用 API 或 API Key。

| 概念 | 定义与沿用规则 |
| --- | --- |
| Provider / 配置实例 | 服务商或接入渠道在本地的一个独立配置；沿用稳定 providerId。相同厂商/预设可以创建多个实例，各有目标、模型、Key 引用及确认状态 |
| Model | 服务商/渠道实际接受的模型 ID；运行身份是 (providerId, modelId)，保留完整原始 ID，不以同名、别名或底层模型相同合并不同渠道 |
| Adapter | 协议实现；保留原生 OpenAI/Anthropic/Gemini，兼容服务尽量复用 R09 OpenAI-compatible，不按品牌复制 SDK/HTTP/SSE/重试代码 |
| Preset / Catalog | 经核验的创建配置用元数据模板，独立 preset 标识和修订；不是 Provider 实例、Key、可执行插件或授权凭证。选中后生成新实例，不能共享凭据或覆盖既有实例/历史 |

当前源码依据：`src/shared/schemas/configuration.ts` 已有独立 ProviderConfiguration、协议 kind、customModels 和成员 providerId/modelId；`src/main/providers/ProviderRegistry.ts` 已有 Main-only policyResolver/capabilitiesResolver 与未知能力拒绝。以上是复用位置，不表示目录已经存在。品牌名称不逐个加入现有 ProviderKind 协议枚举。

## 未来目录数据要求（尚未冻结 wire shape）

| 信息 | 录入与安全要求 |
| --- | --- |
| 目录身份 | 稳定 preset 标识、服务商/渠道标识、展示名称、修订；聚合/第三方渠道明确运营方及实际凭据接收目标 |
| 协议与默认目标 | 明确已有 Adapter 类型；默认 Base URL 必须对应官方 API 文档、规范化并经现有目标验证。未核实则不填可用默认值，不猜 URL |
| 鉴权形式 | 仅描述已实现 Adapter 支持的鉴权机制/受限字段；无 Key 值、账号、Cookie、代理凭据或任意可执行表达式。未支持的鉴权方式标未实现，不靠模板绕过 |
| 模型选择 | 可选的经核实模型列表/发现能力及其来源，也允许手动完整 modelId；模型列表失败不阻止保存自定义配置，但不等于允许生成 |
| 能力 | 按具体目标、API 版本、模型记录上下文、最大输出及参数名、stream、推理模式/公开输出和 usage 语义；区分支持/不支持/未知，附适用范围 |
| 核验元数据 | 每条目标/能力/模型事实有官方来源、核验时间、修订及过期/重新核验规则；文档声明、fixture 验证、用户授权真实验证分别留证，不能共用一个“已支持”标签 |
| 费用引用 | 有依据时引用独立价格政策及货币、输入/输出/缓存/推理计费、更新时间和有效期；没有价格就显示未知，不填0、不猜折扣、不自动注册可用预算政策 |

预设选择只填配置默认值；创建、启用、刷新目录、保存 Key 都不自动鉴权、查询模型或生成。目录更新不改变已有用户 Base URL/模型/Key/目标确认，不覆盖旧 Run 冻结快照；应用新默认值须由用户明确编辑并重新走既有撤销/确认规则。目录首版采用可审查的随版本数据；在线目录更新不属于本需求的实施授权。

用户可添加任意自定义 OpenAI-compatible 服务及多个配置实例，“任意”仍受现有协议、HTTPS/目标安全及能力门禁约束；未知协议/参数或未核实能力如实拒绝，不静默回退 Mock。特定服务确有不兼容行为时先用能力配置/fixture 证明差异；只有协议无法表达时才另行申请最小 Adapter 扩展。

## 依赖、实施窗口与文件归属

硬前置是已合入的 R08/R09 配置身份、Key/目标验证和兼容协议；各原生预设只有在相应 R10A/R10B Adapter 实际集成后才能标注为已实现。R11 不新增对目录的依赖。价格/计数缺失的真实生成继续受现有规则限制，费用完善对接 R13。

**推荐窗口**：先让当前 R10A/R10B/R11 按已批准任务书交付并完成必要联合接线；待目录将消费的公共协议稳定、共享文件空闲，再单独授权安排 R08/R09 后续增强。不作为新的 R 任务，不推迟 R11 基线验收，不改变 R12–R18 既定依赖；可否与后续任务并行只按具体文件排他性重新登记。基础目录/自定义实例纳入 V1，不擅自移到 V1.1；UI 精修归 R16，最终验收归 R17。

目录自身交付顺序为：总控冻结目录元数据/兼容性与证据规则 → R08/R09 增强实现及 fixture → 总控公共接线/同房间联合验收。R12–R18 仍按原依赖、各自授权与文件排他性推进，不以目录先完成作为新的开工前置；R13/R16 按各自时机消费目录结果，R17 最终核对本 SPEC 的多服务商要求。具体实现文件集合和分支基线在那次实施授权时登记，本轮不创建目录模块、空接口、UI 或 Worktree。

Shared/Schema、Database/migration、Registry/factory、Main/IPC/Preload/App、状态看板及验证规则继续由总控独占；若须持久化 preset 来源/修订，先提兼容性方案并由总控分配未来 migration，不在本规划中占号或修改已发布迁移。当前三个 Worktree 不得因本文件扩大可写目录；目录契约提案须独立提交给总控，不得直接落到当前分支。

## 后续验收门槛（未执行）

1. 数据校验：缺/伪来源、非法目标、未知协议/鉴权、过期能力/价格不能变成可用政策；Coding 订阅、fixture 证明和真实 API 权益不能混同。列出的服务商分别核验，不能由一个兼容端点外推全部可用。
2. 配置与实例：预设及自定义均可创建多个独立实例；同 modelId 可在不同 providerId 下使用；修改/删除一个实例或 Key 不能影响其他实例，目录升级不静默改配置/历史。
3. 协议复用：至少用两个独立 Provider 实例/不同目标的受控 HTTP fixture 证明复用同一 R09 Adapter；原生 Adapter 另按其实际协议验证；参数、stream/推理/usage 未知或不支持如实展示，不伪造 usage。
4. 安全与分级结果：配置、模型发现、鉴权和生成分别标注；连通/模型列表/401/429 不等于生成成功。生成请求在未授权、能力/计数/价格未知或失效时于读取 Key/发请求前安全拒绝；模型发现和鉴权按各自能力、目标确认及显式触发独立验证，不额外套用生成价格门槛；Key 脱敏、TLS、目标确认、DNS/重定向和费用预留不回退。现有 DeepSeek 特定单次许可/代理白名单不能泛化为所有 Provider 豁免。
5. 同房间联合：来自不同 Provider/不同模型的多个成员完成串行 fixture 协作，后续成员得到前序公共上下文；请求身份/usage/费用归正确实例，取消保留部分文本，切房/重启与旧冻结身份不串用当前配置。使用多个成员不授权并发真实调用。
6. 生产与发布：真实 Main/factory/IPC/Preload/设置/房间选择路径需隔离 Electron 验证。真实 Keychain、逐家公网鉴权/生成、实际费用及跨平台发布另列未验证/已验证证据；真实请求只在另行明确批准目标、场景和金额后执行，不自动付费 smoke。

本次仅文档一致性/链接/文件归属检查，不运行模型、读取 Key 或用户数据，不把未来验收写成 PASS。
