# 发布、授权与外部贡献政策（规划）

2026-10-16 用户确认发布方向。本文约束后续规划，不是许可证授予，也不表示已经公开仓库或完成发布。R00–R18 的功能、模块、依赖及独立 Worktree / 总控合并模式保持不变；R17 实施和对外发布仍须另行授权。

## 产品与分发方向

- 对外统一表述为：**免费、源码公开（Source Available）、非商业授权**。英文：**Free of charge, source available, licensed for noncommercial use**。不得称为 OSI 标准开源或使用暗示无限制商用的表述。
- 未来在用户的个人 GitHub 公开仓库发布源码，通过 GitHub Releases 提供 Windows/macOS/Linux 桌面安装包。具体账号、仓库名、URL 和版权署名待用户确认，不编造地址，也不因本文件存在而创建、推送或公开仓库。
- 软件本身免费、单用户 BYOK；用户自行提供模型厂商 API Key，模型费用由用户按厂商规则承担。“软件免费”不表示模型调用免费。
- 不增加商业收费、会员订阅、激活码、商业支付或反盗版系统。现有 usage、费用估算和预算限制服务于模型调用控制，保留原技术范围。

## 许可证选择与确认门槛

优先考虑 **PolyForm Noncommercial 1.0.0**，禁止未经授权的商业使用；正式发布前须重新核对官方全文、适用范围及版权授权链，并由用户明确确认。MIT、Apache-2.0 不再作为本项目的默认候选。当前不新增正式 `LICENSE`，不修改 package 许可元数据，不把候选写成已生效授权。

允许用途的判断以最终确认的许可证全文为准；PolyForm 文本包含个人用途及非商业组织等具体条款，不能仅凭“企业使用”“机构使用”字样替代条款判断，也不能用本页摘要改写许可证。超出许可范围的商业使用须另获相关权利人授权；这不引入收费产品或商业授权销售流程。

项目自身的授权不覆盖第三方组件的独立权利。第三方依赖、Electron/原生组件、字体、图标、示例与复制代码须保留各自适用许可证、版权及通知；不得把它们统一改标为本项目的非商业许可。Provider SDK 的许可与模型厂商服务条款分别核查。

## 外部贡献与知识产权管理

在开放外部贡献或合入外部代码前，由总控准备、用户确认贡献规则，纳入 R17 发布审查：

1. 明确贡献者仍保留其版权，PR、提交或署名不自动转让版权。记录作者、来源、适用许可和授权证据；核对雇主权利、第三方片段及 AI 辅助内容的来源与可提交权利，不能把生成工具的输出当作权属保证。
2. 明确入站贡献授权与最终确认的项目出站许可衔接，并足以支持项目按该许可分发和修改；不能默认公共 PR 或平台可见性已授予项目所需的全部权利。来源或授权不清的代码先不合入。
3. 评估来源声明、DCO 或 CLA 的适用性。DCO 不等于版权转让或额外再许可授权，标准 DCO 1.1 使用开源许可措辞，不能直接假设适配本项目的非商业许可。是否采用 CLA、转让或其他贡献协议须经用户确认，本轮不启用签署系统或机器人。
4. 若未来另行考虑商业例外或变更许可证，先核对所有相关贡献的授权；缺少所需权利时须取得同意或移除/替换相关内容，不能因维护者身份推定拥有全部权利。第三方通知和贡献记录持续保留。

具体贡献协议、版权主体、署名与联系信息尚未确定；本政策不代替这些文件，也不追溯声称现有代码已经完成权属审查。

## R17 最终发布门槛

以下是未来验收条件，当前均未执行。与 [R17 任务](../tasks/R17-e2e-release.md)的功能、隔离 E2E、原生 ABI 和跨平台验收共同成立：

| 门槛 | 必须提供的证据与停止条件 |
| --- | --- |
| 正式许可证 | 用户对准确名称、版本、版权主体和适用范围的确认；根目录许可证全文与官方原文核对记录，源码及安装包内可取得许可证和所需通知；仅链接或摘要不满足项目验收 |
| 版权及第三方审查 | 按实际发布锁文件和包内容列直接/传递依赖、原生组件及其他素材的版本、来源、许可、版权和分发义务；核查兼容性并随包保留通知，冲突未解决不得发布 |
| README 中英文说明 | 一致说明软件免费、Source Available、非商业使用限制、BYOK/厂商费用、最终许可证全文位置及贡献规则；不得称 OSI 开源，不用宽松许可徽章误导 |
| Git 历史敏感信息 | 检查当前树及拟公开 refs 可达的完整历史、分支/标签和待上传资产中的 Key、数据库/备份、私有配置及个人敏感信息；记录扫描范围、工具/人工复核和结果，不在报告复写秘密；发现问题停止公开，先处理凭据，再申请历史清理方案，不擅自重写原始历史 |
| GitHub 仓库准备 | 用户确认个人账号/仓库名、公开范围、版权/贡献与安全反馈入口；复核待推 refs、标签、权限和 CI 秘密隔离；本地可审阅材料完成后，再获明确授权执行创建/推送/公开 |
| 跨平台 Releases | Windows/macOS/Linux 在对应环境验证构建、包内许可证/第三方通知、安装启动和必要流程；记录版本/tag/Commit、OS/架构、校验和及签名/公证状态；安装包作为 Releases 资产，自动生成的源码归档不能替代安装包；缺平台证据不能宣称三平台发布验收完成 |
| 最终发布审批 | 汇总真实验证矩阵、已知限制、贡献权利及上述门槛，用户审核具体版本后才发布；技术验收、签名、公证、上传及公开分别记录，未执行项目保持未验证 |

## 官方依据与复核入口

- [PolyForm Noncommercial 1.0.0 官方源码文本](https://github.com/polyformproject/polyform-licenses/blob/1.0.0/PolyForm-Noncommercial-1.0.0.md)：本轮查阅的候选原文；发布前重新核对。
- [OSI Open Source Definition](https://opensource.org/osd)：开源定义允许商业领域使用；本项目使用 Source Available 定位。
- [GitHub 仓库许可说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)：公开可查看/fork 与完整版权授权不能混同。
- [GitHub Releases](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)：版本、标签、说明与二进制资产的发布入口。
- [Developer Certificate of Origin 1.1](https://developercertificate.org/)：仅作未来贡献机制评估依据，本项目尚未采用。
