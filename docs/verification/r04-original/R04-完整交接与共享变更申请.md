## 2. 已完成行为与使用方法

现有 Main 方法签名保持不变，可直接用已有 IPC/Preload 命令调用；Renderer 正式重试/恢复交互及共享语义登记仍待总控集成。

| 控制 | 本次实际语义 |
| --- | --- |
| Start | 校验输入、房间和成员，冻结真实有序成员信息；在提交通知前建立全局门禁与真实完成 Promise。每次只启动一个 Run。 |
| Pause | running → pausing；当前已执行 Turn 正常结束再暂停，不 Abort。pausing 重复 Pause 幂等；未开始的下一 Turn 不调度。最后一个 Turn 完成优先进入 completed。 |
| Step | 仅 paused；拒绝并发重复 Step；执行一个新逻辑 Turn。三成员、maxTurns=1 的 step Start 一次即 completed。 |
| Resume | 仅 paused，切 automatic 并沿已知 nextTurnIndex 调度；不重置累计时间。冻结成员按 turnIndex 对成员数取模，支持超过一轮的持续串行执行。 |
| Stop | running/pausing/paused → cancelling → cancelled；传递 AbortSignal，保留已提交部分文本；取消中重复 Stop 等待同一 Promise，cancelled 再 Stop 幂等。晚到结果不写库。 |
| Inspect | 仅 interrupted，纯读取决策，不写状态、不发请求；getSnapshot/subscribe 返回安全投影。 |
| Discard | interrupted → cancelled；保留所有旧请求、消息和事件。 |
| Retry | error/cancelled/interrupted 的最新逻辑 Turn、最新 failed/aborted/interrupted Attempt；同 Turn 新 requestId/messageId/attemptIndex，不覆盖旧 Attempt 和消息。 |
| Continue | 同上，且只能续写最新 Attempt 对应的非空部分消息；复用旧输入，追加旧部分输出 assistant 与固定续写 user 指令。新消息只存本次后缀；不实现 R12 编辑/版本分支。 |
| Recovery resume | 完整元数据且所有逻辑 Turn 及其最新 Attempt 已完成时，按冻结进度继续；不会重发旧 interrupted 请求。保留原 mode。 |
| Recovery retry | 显式重试最后一个可重试 Turn；生成新请求身份和消息。旧证据原样保留。 |

普通完成、取消、错误终态不能通过 Step/Resume 自动复活；completed 不接受重试或恢复。error/cancelled 只允许上述显式重试/续写。legacy NULL task/members/progress/elapsed 不猜测、不补零，生成类恢复仍返回 unsupported；inspect/discard 可用。没有旧进程 context 的持久 paused 可在完整、已结算证据下显式 Step/Resume 重建，或 Stop；正常启动仍沿用 R03 的 interrupted 分类。

## 3. 状态转换表

Run 状态变更由 setRunState → transitionRun 统一检查；原子提交状态与事件。

| 当前 Run | 允许的下一状态 |
| --- | --- |
| idle | running |
| running | pausing、paused、cancelling、completed、error、interrupted |
| pausing | paused、completed、error、cancelling、interrupted |
| paused | running、cancelling、interrupted |
| cancelling | cancelled、interrupted |
| cancelled | running（仅显式 Retry/Continue） |
| error | running（仅显式 Retry/Continue） |
| interrupted | running（显式恢复/重试）、cancelled（Discard） |
| completed | 无 |

| 当前 Turn 聚合状态 | 允许的下一状态 |
| --- | --- |
| queued / pending | running、cancelled |
| running | completed、failed、aborted、interrupted、cancelled |
| failed / aborted / interrupted | running，仅显式新 Attempt |
| completed / cancelled | 无 |

Turn 是最新尝试的聚合投影；Attempt 终态由 R03 DB 规则保护，不会重开。原 Turn.requestId 始终保留第一次请求，快照当前 requestId/messageId 指向最新 Attempt，订阅用 attempts 关联历史事件。

## 4. 全局锁、执行时间和异常收尾

- 一个 Main RunService 的全局锁覆盖全部房间，paused 保持锁。注册 context/Promise 早于同步 afterCommit 通知，阻止重入 Start；终态提交后释放锁。Main 仍只装配一个 RunService，不新建第二个调度事实源。
- 软 Pause、Stop 与 Resume 竞争均由 Main 判定；重复 Step/Resume 被拒绝，不依赖 UI 禁用按钮。Stop 优先阻止后续调度；Provider 自行返回 cancelled 也经合法 cancelling 路径收尾。
- 每个执行段使用 performance.now；累计值从 R03 elapsedExecutionMs 续用，暂停间隔不计。文本/Turn/Run 提交时落库；最终状态、elapsed 和 currentTurnId/currentAgentId 清理同事务。
- 剩余总时限有可 Abort 的 timer，并在循环、上下文构建后、请求前及每个 chunk 到达时再检查单调时钟，覆盖长时间无响应、立即连续输出导致 timer 饥饿、通知期间预算耗尽。大于32位时限分段设 timer。
- 时限耗尽：Run error，活动 Turn/Attempt aborted，消息保留，turn_aborted.error.code=timeout，Run 原因使用既有 Maximum run duration reached；时间耗尽的显式重试拒绝，不刷新预算。
- 原生输出上限由 input.outputTokenLimit 交给 Provider。RunService 不把 delta 数当 Token。Mock usage 明确为 UTF-16 输入长度/输出 delta 单位估算，不能作为真实模型用量或计费证明。
- Provider finish.length/content_filter 不能冒充正常完成：保留部分消息并 failed，Run error，安全私有 lastError 保留准确 finish reason。当前公开错误为既有 invalid_response；专用原因/错误语义见共享申请。
- 不合作的 iterator.next/return 不阻塞逻辑 Stop/shutdown；主流程与 Abort 竞争，旧流每个结果检查原 Signal，晚到结果无写入路径。不保证第三方网络在忽略 Abort 时物理取消，后续真实 Adapter 必须正确关闭底层资源。
- shutdown 同一 Promise 屏障，先阻止新调度，排空一次已就绪的输出回调再 Abort，不等待新的 Provider I/O；paused 终结为 cancelled，保留 R01 既有退出回归。
- 数据库短暂收尾失败不会悄悄释放运行权：原错误向调用者返回，冻结执行段并保留锁；存储恢复后再次显式 Stop 可完成持久收尾。父 Run 终态和仍活动的子项状态/事件同事务结算，避免 error 父项留下 running Attempt。

## 5. 请求、事件、恢复证据

- 每次请求由 Main 分配唯一 requestId，Provider 必须原样使用；每个 Attempt 有独立消息和不可变输入快照，Signal 不入库。
- 新逻辑 Turn 的 nextTurnIndex 由 R03 insertTurn 同事务推进；同 Turn Retry/Continue 不再分配 Turn 或推进逻辑回合数。
- turn_started 在 Turn/Message/Attempt/指针提交后立即通知，早于模型输出。沿用 R03 appendRunEvent 返回的确切对象和 afterCommit，不全量读取事件找最后一条。
- 每个 Run 的 sequence 持久严格递增。事务回滚没有幽灵通知；测试注入 Start/Turn/终态事件失败，验证无重复序号或丢失锁。历史订阅仍使用 R03 一致快照及有界游标。
- 磁盘重开测试实际使用私有临时 SQLite；inspect 零请求，显式 retry 新请求/消息/Attempt，旧请求输入、输出、状态、事件字节一致。无自动重发。
- 普通快照仍排除 inputSnapshot、providerRequestId 等 Main 私有证据；保留 R02 流顺序、身份、脱敏和凭据字段守卫，R01/R02/R03 回归包含在全量测试中。
