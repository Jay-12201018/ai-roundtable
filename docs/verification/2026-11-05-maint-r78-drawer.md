# 探针维护：R07/R08 抽屉偶发打不开（2026-11-05）

分支 `codex/maint-r78-drawer`，基于 `codex/image-input` 的 `ba6bf57`（发图片当时还没合进 main，合并后需要 rebase）。

## 现象

`tests/probes/r07r08-electron.cjs` 在完整检查里失败过两次（等待 3 秒和 10 秒各一次），报错都是 `Layout 1 (800×600 light 讨论): Navigation drawer did not open`。单独重跑能通过。

## 根因

点击被应用自己的 effect 抵消了，等多久都不会好。

1. 窗口从宽屏缩到窄屏，`src/renderer/App.tsx` 里 `useEffect(() => { setNavOpen(false); ... }, [layout])` 会关抽屉。
2. React 把 `resize` 算作非紧急事件（`getEventPriority` 返回 8），所以 effect 不在提交时同步执行，而是晚一个任务。
3. 窄屏布局已经上屏、effect 还没执行时，探针的轮询可能正好看到菜单按钮并点击，`setNavOpen(true)` 入队。
4. React 处理这次点击前先执行积压的 effect，`setNavOpen(false)` 排在后面，抽屉就没开。此后布局不再变化，也没有人再点，所以 3 秒和 10 秒超时都一样失败。

`Layout 1` 是整轮探针里唯一一次从宽屏切到窄屏后马上点菜单，这和失败只出现在这一项相符。

### 原来的遮挡假设

**不成立。** 探针关掉了后台节流，窗口被盖住时，页面仍是 `visible`、约 120 帧/秒，动画正常走完。盖住窗口时，默认节流的见证窗口是 `hidden`，说明确实盖住了。

最小化时帧数确实降到 0，抽屉动画曾停在 `running`、进度 0 ms，但最终走完了，只是慢。

### 是探针问题还是应用问题

竞态在应用代码里，但实际可丢点击的时间窗很窄（`setTimeout 0` 还会丢，延迟 1 ms 就不丢）。真人很难点中，点中也只是这一下没反应，再点一次就好。探针的轮询能碰上，是因为它在按钮出现后的同一个任务里就点击。

没有在探针里等 effect 执行完，因为那只是绕开问题，而且要依赖 React 内部时序。关抽屉改到渲染时做只有几行，其他探针和真实用户都受益，所以修了应用。

### 另一个问题：最小化时卡满 240 秒

那 5 轮走完了前 6 项布局，卡在第一次截图：窗口最小化后改过大小，`capturePage` 不再返回（独立实验确认，4 秒未返回），而且这一步原来没有期限。

## 改动

- `src/renderer/App.tsx`：布局变化时关抽屉，从 effect 改为渲染时做，和布局变化在同一次提交里生效，中间没有空档。
- `tests/unit/rendererShell/drawerLayout.test.tsx`（新）：
  - 布局刚切换就点菜单，抽屉要打开。这个测试用真实调度，不走 `act`，修复前失败（`expected null not to be null`），修复后通过。
  - 换布局关抽屉、切回来不会自己打开、同一布局内改大小不关，修复前后都通过，确认行为没变。
- `tests/probes/r07r08-electron.cjs`：
  - 任何一步失败，错误信息都带现场：`.drawer.is-left`、`.drawer.is-right` 是否存在、`visible()`、每个动画的名字和 `playState`、`document.visibilityState`、`document.hasFocus()`、窗口是否被遮挡、`innerWidth`、帧数、时间线走了多少、等待期间的变化和点击轨迹。
  - 截图前如果窗口最小化就先恢复，截图限时 10 秒。
  - 没有放宽或删除断言，没有 retry 和 skip，也没有拉长等待。
- `tests/probes/window-condition.cjs`（新）：让探针在失焦、遮挡、最小化下运行，结束时输出实际状态，确认这一轮真的处在那个条件下。
- `tests/probes/r78-drawer-acceptance.cjs`（新）：实操验收，真实鼠标键盘。

遮挡判断：`isVisible()` 被盖住时仍是 `true`，不能用。现在用 `osascript` 查窗口服务器，看有没有一个窗口完整盖住探针窗口，只在失败时查，不需要屏幕录制权限。实测：遮挡时是 `by Electron`，前台、失焦、最小化都是 `false`。

## 遗留问题

1. 原来的失败没有在非最小化条件下自然复现，见上。
2. 最小化时探针能过，但很慢：每轮 44–63 秒（正常约 10 秒），前 6 项布局平均每项约 7–10 秒，每项期限是 20 秒，余量不算宽。第一次截图后窗口就恢复了，所以后面的布局不是在最小化下跑的。
3. 没有测试屏幕锁定、显示器睡眠和窗口在别的桌面空间，这些都可能让页面拿不到帧。为了不打扰正在用电脑的人，没有去触发。
4. 其他探针的 `capturePage`（`r16-harness` 等）没有改，窗口最小化后改过大小同样会卡住，只是这些探针改大小的时机不同，没有验证。
5. 未验证：桌面 E2E、打包版、Windows。
6. 探针按设计保留临时目录，这次又在系统临时目录下增加了一批 `roundtable-*`，都是假数据，没有清理。
