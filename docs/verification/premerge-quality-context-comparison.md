用 fixture 复现实测中的场景：三人圆桌（起草者 Drafter、综合者 Synthesizer、审查者 Critic），主持人把综合者发言里的预算从 2000 改成 1500 之后，重新生成审查者。两边输入完全相同，分别交给修复前（`b3e3324`）和修复后的 `buildPublicContext`，用 DeepSeek 生产计数器（UTF-8 字节上界）计数。发言内容是编写的示例，不含真实输出、Key 或数据库 ID；成员 ID 为 fixture 值。

生成方式：把 `b3e3324` 的 `src/` 导出到临时目录，与当前分支的 `src/main/context/buildPublicContext.ts` 一起用 esbuild 打包，以同一份输入各调用一次（脚本在会话临时目录，未提交）。自动化测试里的同类断言见 `tests/unit/context/discussionFormat.test.ts`。

## 审查者现在看到的上下文

1. 它是谁：成员「审查者」，角色 Critic；本场还有起草者、综合者。主持人没写提示词，应用给了内置的审查指引——逐条指出具体问题、写明出处、给可执行的修改建议，不重写、不笼统夸。
2. 规则：不要复述别人；以主持人最新修改为准；不要在开头写自己的名字或标签。
3. 讨论记录：任务、起草者的方案（预算 2000）、综合者的发言（**已由主持人修改**，预算 1500，并明确"以此为准"）。三段都在同一条 user 消息里，每段有应用写的标签，原文全部是 `> ` 引用。
4. 最后一句：现在由你（审查者）发言，给出你这一角色新增的贡献。

这只是输入侧的修复。模型实际是否不再照抄、是否采用 1500，需要用真实 DeepSeek 复测确认（**待总控与用户一起做**）。
