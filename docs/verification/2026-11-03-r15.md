### 实操发现并修复的问题

| 问题 | 修复 |
| --- | --- |
| 跳过的文件全写"没有勾选"，但内容相同、路径无效、符号链接这些行根本没有勾选框 | Main 按各自的原因记录和返回 |
| 覆盖行同时有"覆盖"勾选框和"覆盖"标签，新建行写"写入"却标"新建" | 勾选框文字就是这一行会做的事（新建 / 覆盖），能勾的行不再加标签 |
| 界面叫"检查"，失败原因却说"预览" | 统一成"检查" |
| 结果页里没写入的文件埋在列表中间；"重新检查"出现两次 | 没写入的排最前；目标变化时只保留说明旁边那一个 |
| 写入记录把代码内容往下推一大段，文案还出现"没有写入，1 个没有写入" | 状态行已写最近一次，记录默认收起；文案理顺 |
| 隐藏路径（如 `.github/workflows`）可能被其他工具自动读取或运行 | 无法靠拦截解决，在这一行写明提示（`.git` 直接拒绝） |

写决策时自查发现的：写临时文件期间父目录被换成链接，原本只在写之前查过（已加放置前复查和测试）；不支持硬链接时直接写失败会留下半成品（已删除半成品并加测试）。

## 第 3 层：真实模型实测的替代

R15 不调用模型，不需要真实模型实测。改为**总控和用户一起在试用版里写入用户自己选的测试文件夹，未验证**。建议脚本（不花钱：Mock 讨论和 Mock 代码候选都是本地生成的）：

1. 准备测试文件夹（不要选真实项目），在终端执行：
   ```sh
   mkdir -p ~/Desktop/r15-试写/src/mock ~/Desktop/r15-外面
   printf 'export const hello = "旧内容";\n' > ~/Desktop/r15-试写/src/mock/hello.ts
   printf '# 试写\n' > ~/Desktop/r15-试写/README.md
   printf '根外的文件\n' > ~/Desktop/r15-外面/秘密.txt
   ln -s ~/Desktop/r15-外面 ~/Desktop/r15-试写/shared
   ```
2. 启动隔离试用版：`pnpm trial`（不接触真实数据库；migration 13 只作用于试用 profile）。首次进入点"开始试玩"得到 Mock 房间；如果试用 profile 里已有内容，新开一场 Mock 成员的讨论即可，不必重置。
3. 讨论结束后：本场信息 › 产物 › 代码候选 › 生成…（写着内置 Mock，不花钱）。Mock 候选只有一个文件，所以点"修改…"，把内容换成下面这份再保存（主持人修改的版本直接有效）：
   ```json
   {"title":"试写","summary":"验证写入。","notes":[],"files":[
     {"path":"src/mock/hello.ts","language":"typescript","description":null,"content":"export const hello = \"新内容\";\n"},
     {"path":"src/new/world.ts","language":"typescript","description":null,"content":"export const world = 1;\n"},
     {"path":"docs/说明.md","language":"markdown","description":null,"content":"# 说明\n"},
     {"path":"README.md","language":"markdown","description":null,"content":"# 试写\n"},
     {"path":"aux.ts","language":"typescript","description":null,"content":"export {};\n"},
     {"path":"shared/x.ts","language":"typescript","description":null,"content":"export {};\n"}]}
   ```
4. 点红色的"写入文件夹…"，读一遍说明；先在系统对话框里点取消，确认什么都没发生；再选 `r15-试写`。
5. 看检查结果：应为新建 2、覆盖 1、内容相同 1、不能写入 2（`aux.ts` 保留名、`shared/x.ts` 符号链接），差异看得懂，默认一个都没勾。
6. 只勾 `src/new/world.ts` 和覆盖 `src/mock/hello.ts`，看按钮怎么变，点写入；在访达里核对：只有这两个文件变了，`docs` 没有出现，`r15-外面` 没变，文件夹里没有 `.roundtable-tmp`（隐藏文件用 `ls -a` 看）。
7. 回到编辑版本再做一次覆盖竞态：用"修改…"把 `hello.ts` 的内容再改一版并保存，点"写入文件夹…"（会立即重新检查），勾上覆盖；**先**用编辑器改 `~/Desktop/r15-试写/src/mock/hello.ts` 并保存，再点写入：应被拒绝并保留你的改动；点"重新检查"看新差异。
8. 退出重开：写入记录还在，文件夹要重新选。结束后手动删除两个测试文件夹；试用 profile 不想留可以用 `pnpm trial:reset`（只删试用 profile，里面的内容会一起删掉）。

重点请用户判断：默认全不勾是否太麻烦（有"勾选全部新建文件"）；红色的使用是否恰当；文案是否直白。

## 契约与数据库影响

新 migration 13（只追加，恢复校验已覆盖），新通道 `codeExport.chooseRoot / preview / write`，`artifactVersion.codeWrites?` 可选字段，错误字段只增。详见 CONTRACTS。**合并前 migration 13 不得作用于用户的真实数据库。**

## 遗留问题与残余风险

1. 残余竞态（D129）：Node 没有 `openat` / `renameat`，最后一次检查到放置之间有极短窗口。外部程序恰好在这时改目标，改动会被替换；同一用户权限下专门针对这个窗口的恶意进程不在防御范围内。
2. 写入中途崩溃（D129、D130）：可能留下 `.roundtable-tmp` 文件；已写入的文件可能没有记录。先写盘再记录，所以不会有"记录说写了而其实没写"。
3. 几 GB 的现有文件：内存不再是问题，但预览和写入前都要完整算一遍哈希，要花时间。检查期间可以关闭对话框；写入期间不能。
4. Windows、Linux 和网络盘未实测，发布前按 R17 验证。`O_NOFOLLOW` 在 Windows 上不存在（退化为依赖 `lstat` 检查），目录 flush 在部分平台不可用（已忽略错误）。
5. 写入的文件之后被其他工具如何使用（`package.json` 脚本、编辑器任务、CI）不在控制范围内；只有 `.git` 被直接拒绝，其他隐藏路径只提示。
6. 不可见字符规则会拒绝少数真实名字（ZWJ 连接的 emoji、含 ZWNJ 的波斯语），这种文件可以写入后再改名（D127）。
