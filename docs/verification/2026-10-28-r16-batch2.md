### 探针迁移说明（不放宽断言）

- **设置页**：旧探针里"模型设置"页的表单操作改为走连接向导（选服务 → 填 Key → 保存并连接）和服务卡片（更换 / 删除 Key、高级与删除）。
- **房间页**：旧的"房间与成员"管理页改为侧栏房间 + 房间单页 + 成员对话框；工作流配置改为讨论方式对话框。
- **外观**：从顶栏移到 设置 › 外观，探针改到那里切换浅色 / 深色。
- **有意改变的行为**，探针改为断言新行为：r09 重启阶段不再确认地址就能发送（D113，原断言"重启后必须重新确认"）；r07r08 / r09 SQLite 核对迁移版本到 11，并新增"批准行与当前 Key 修订号一致"的检查；Bridge 分组增加 `network`、`app`，settings 增加 `listModelReadiness`；r07r08 重启阶段先从房间页打开讨论再核对（布局检查最后停在房间页，房间页显示房间而不是讨论）。
- **去掉的一步**：r07r08 的"筛选已归档"步骤——新界面没有筛选，已归档房间在侧栏折叠列表里，探针改为从折叠列表打开并核对历史。

## 第 2 层：实操验收（真实构建 + 隔离 profile）

探针 `tests/probes/r16-batch2-acceptance.cjs` 用构建出的真实应用，在隔离临时 profile 中通过 CDP 模拟真人点击和键盘输入（中文用输入法组合事件 `Input.imeSetComposition` → `insertText` 提交），Mock 与本地 DeepSeek 夹具，网络阻断（代理检测用探针自带的 CONNECT 夹具）。三个阶段使用同一个 profile：

1. 首次：欢迎页 → 开始试玩 → 演示讨论完成；向导连接夹具 DeepSeek → 自动建"我的第一场讨论"；改房间名、加成员（角色模板、中文名）、停用成员、键盘排序；讨论方式改为审查修订链 → 开始，阶段进度与阶段标签；预算很小的一场因预算停下（不出现灰色的重试 / 续写）；删除没讨论过的房间；用量页本月 / 上月；网络与代理设置、检测、保存、立即重启（重启被记录而不真正执行）。
2. 重启 1：DeepSeek 仍"可以使用"、不再确认（D113）；代理来源为"这个页面的设置"；关掉代理保存、立即重启。
3. 重启 2：直连；重启后直接开始讨论无需确认；换 Key 后状态变为"需要确认地址"、开始被拒并写明原因、确认后可以开始；800 宽换 Key 向导；深色服务页。
